### 골드셋 운영이 정교하다 — 우리가 오늘 겪은 문제를 이미 처리해뒀다

`agent/mapping/golden_set.py` 에 두 가지 장치가 있다.

**① `match_status="매칭 실패"` 19건을 평가에서 제외**

> 애초에 KOSIS에 정식 등재된 통계가 없는 케이스(관세청 잠정치 등)다. 어떤 임베딩/리랭커를
> 써도 못 맞히는 게 정상이라 Recall@K/MRR 계산에서 반드시 제외해야 한다 —
> 안 그러면 **카탈로그 공백을 "모델이 못 찾음"으로 착각**하게 된다.

**우리가 오늘 하루 걸려 발견한 것과 똑같은 문제의식이다.** 우리는 177건 중 43~52건이
KOSIS 로 검증 불가능한 주장(비트코인·롤렉스 판매가·전망치)인 걸 모른 채
"검색 실패 66건" 으로 세고 있었다. 그쪽은 골드셋 단계에서 사람이 라벨로 걸러냈다.

**② `TABLE_ID_OVERRIDES` — 정답 tblId 를 카탈로그 실재값으로 치환**

골드셋의 정답 40건 중 31건이 카탈로그에 없는 tblId 였는데, 그중 상당수는
"같은 통계가 다른 tblId 로 이미 들어있는" 경우였다(소매판매 `DT_1K41013` → `DT_1K41017`).
override 없이 재면 카탈로그에 정답이 있는데도 "못 찾음"으로 집계된다.

미검증 항목은 주석으로 명시해뒀다 —
`DT_1DA7002S` vs `DT_1DA7102S` 는 "어느 쪽이 맞는지 라이브 API로 검증하지 않았다.
일단 카탈로그 기존값을 신뢰하기로 하고 override 에 넣었다" 라고 적어둔다.

## 3. 표 검색 — 큐레이션 vs 크롤

| | 그쪽 | 우리 |
|---|---|---|
| 표 풀 | **54개** (손으로 큐레이션) | **107,138개** (전체 크롤) |
| 표당 메타 | `title` / `keywords` / `description` / `embedding_text` / `related_tblId` 를 사람이 작성 | 자동 수집 |
| 검색 입도 | **표(tblId)까지** | **좌표(org+tbl+itm+objL1~8)까지** |
| 좌표 확정 | `table_params.json` 에 수동 정의 | 자동 조합 + API 검증 |
| 인덱스 | 표 54개 임베딩 | 좌표 117,869개 임베딩 |

**입도는 우리가 한 단계 깊다.** 그쪽은 "어느 표인가"까지 풀고 그 안의 항목·분류는
`table_params.json` 에 손으로 박아뒀다. 우리는 그 안까지 자동으로 찾으려다
`EMPTY_RESPONSE` 와 씨름했다.

**대신 그쪽은 실측 성적이 있다.** keyword_search 단독으로 top-1 **69.5%**, Recall@3 **74.6%**.
우리는 좌표 재현율 프록시로 44.8% 인데 기준이 달라 직접 비교는 안 된다.

## 4. 임베딩·리랭커 — 결론이 우리와 다르다

| | 그쪽 | 우리 |
|---|---|---|
| 임베딩 | Qwen3-Embedding-4B (비교 실험 top-1 70%로 채택) | BGE-M3 |
| 리랭커 | BAAI/bge-reranker-v2-m3 (동일) | 동일 |
| 하이브리드 | keyword + embedding 병합 → rerank | dense + lexical → RRF → rerank |
| 현재 상태 | **임베딩 비활성**(`KOSIS_DISABLE_EMBEDDING=1`, 하드웨어 문제) | **종료 판단**(A 64.8% vs C 58.4%) |

흥미로운 건 **양쪽 다 임베딩이 실전에서 안 켜져 있다**는 점이다. 이유는 다르다 —
그쪽은 하드웨어 문제로 못 켰고, 우리는 켜서 재본 뒤 베이스라인보다 나빠서 접었다.

그쪽 설계 문서에 이런 경계가 있다:

> Top-3, Top-5 accuracy 추가: embedding은 top-1에서 약해도 top-3 안에 정답이 있으면
> 리랭커가 구제할 여지가 있음 — 이 구간을 분리해서 보지 않으면 "embedding이 쓸모없다"는
> **성급한 결론**으로 이어질 위험이 있음(이전에 이미 한번 겪은 논쟁).

우리 결론(ChromaDB 종료)은 top-10 재현율과 api_valid 로 냈으므로 이 함정은 피했다.
다만 골드가 없어 절대 recall 은 여전히 못 잰다.

## 5. 판정(verdict) — LLM 위임 여부가 갈린다

| | 그쪽 `judge.py` | 우리 `kosis_verify_claim_values.py` |
|---|---|---|
| 1차 | 코드 규칙 | 코드 규칙 |
| 애매하면 | **HCX-003 / HCX-007 로 위임** | 규칙으로 끝 (`판정보류`) |
| 오차 기준 | %류는 %p, 그 외 상대오차 | 동일한 발상 (`rate_like` 분기) |
| 허용 오차 | 0.1, 5배(0.5) 넘으면 즉시 불일치 | 1.5% / 4% 3구간 |
| 복합 추론 | 여러 claim·표를 한 번에 HCX-007 | 없음 |

설계 철학이 명시돼 있다:

> 규칙 필터는 "명확한 경우만 걸러내고, 나머지는 보수적으로 LLM에 위임"하는 방향으로
> 설계했습니다 (반대로 하면 **애매한 걸 코드가 잘못 확정 판정할 위험**이 큼).

우리는 애매한 걸 `판정보류`·`LIKELY_MISMAPPING` 으로 남기고 사람에게 보낸다.
**같은 문제의식에 대한 다른 해법** — 그쪽은 LLM 에, 우리는 사람에게 넘긴다.

### 우리와 똑같이 겪은 버그

`judge.py` 주석에 실제 배치 실행에서 재현된 버그 두 개가 적혀 있다.

- **한글 복합 숫자**: "23만8천명" 을 8000명으로 읽어 정상 기사를 오탐 → `_find_compound_numbers` 로 수정
- **단위 오판**: `claim.unit="명"` 인데 `claim_type="증감률"` 이라 percent 로 취급,
  실제 차이 0.13% 를 "317%p 차이" 로 계산해 오탐

우리도 오늘 **부호 손실**(`9월(-0.4%)` 의 마이너스가 빠져 차이가 1.01%p 로 부풀었다)로
같은 부류의 버그를 잡았다. 수치 파싱은 양쪽 다 반복해서 사고가 나는 지점이다.

## 6. 우리가 배울 것

### ① claim 단위 diff 를 표준 절차로

> 집계 지표(Recall/MRR)만 보면 이번처럼 "개선 1건 + 악화 2건" 이 상쇄돼
> 안 보이는 회귀를 놓칠 수 있다.

실제로 V4 는 Recall@3 이 그대로였는데 top-1 이 V1 수준으로 회귀했다.
우리도 게이트 규칙을 고칠 때마다 **건별 diff** 를 봐야 한다
(지금은 실버 tier 교차표로 오탐만 보고 있다).

### ② keyword 충돌 방지 기준 — 우리 "기술무역수지" 사고와 같은 부류

> 일반 명사 단독 등록 금지: "무역통계", "물가", "지수" 처럼 여러 표에 공통으로
> 해당될 수 있는 단어는 단독으로 등록하지 않는다.
> 쌍둥이 표(원지수/계절조정, 총괄/세부) 우선 점검.

그쪽은 `무역통계` 를 `DT_1R11006_FRM101` 에 넣었다가 다른 표의 공식 발표명
("기업특성별 **무역통계**")과 겹쳐 오탐을 만들었다.
우리는 `무역수지` 로 검색해 **기술무역수지** 표에 오매핑됐다. 원인이 같다 —
**일반명사가 다른 표의 고유명칭 안에 들어있는 경우.**

### ③ 표 카탈로그에 `description` 을 쓰는 것

그쪽 `embedding_text = title + keywords + description` 이고,
description 에 "기관명·API 검증값·다른 표와의 차이점·한계" 를 사람이 적는다.
우리 좌표 document 는 메타 필드 나열뿐이라 **표를 구분하는 서술이 없다.**
좌표 재현율이 44.8% 에 머문 원인 중 하나일 수 있다.

## 8. 정리

**같은 문제를 다른 쪽 끝에서 풀고 있다.**

- 그쪽: 표 54개를 손으로 잘 만들고 → 골드셋으로 재고 → 판정까지 완주 → 챗봇
- 우리: 표 10만개를 자동 수집하고 → 좌표까지 자동 확정 → 검증 품질을 깊게 팜

**가장 시급한 격차는 골드셋이다.** 그쪽은 59건으로 모델 교체 전후를 숫자로 비교하는데
우리는 지금도 recall 을 못 잰다. 오늘 ChromaDB 를 접은 판단도 프록시 지표 기반이라
"C 가 어떤 지표로도 낫지 않다" 까지만 말할 수 있었다.

그쪽 골드셋 규모(59건)는 우리 확정 집합(125건)의 절반이다. **전수 라벨이 아니어도
비교는 가능하다**는 걸 보여준다.
