# 깨끗한 재실행 런북

현재 산출물은 중간중간 손으로 패치해서 만들었다.
`evaluation_set_v6.csv` 는 `prepare` 를 거치지 않고 파이썬으로 직접 대상을 지운 것이고,
표 후보는 옛 대상으로 뽑힌 것을 그대로 썼다. **숫자는 맞지만 재현 절차가 한 줄기가 아니다.**

이 문서는 처음부터 끝까지 한 줄기로 다시 돌리는 순서다.
**총 1.5시간쯤 걸리고 대부분 기다리는 시간이다. 통으로 시간이 날 때 시작할 것.**

## 시작 전

- **추출은 다시 하지 않는다.** `05_hcx_measurements.csv`(원본)를 쓴다.
  `_v2`·`_v3` 는 프롬프트 실험 실패작이다(아래 「하지 말 것」).
- GPU 런타임 · `KOSIS_API_KEY` · Drive 마운트 · `pip install -r requirements-ml.txt`

## 순서

**1. BGE 표 인덱스** (~20분, GPU)

```bash
python kosis_build_embedding_index.py \
  --table-index kosis_table_summary.csv \
  --output data/indexes/kosis_bge_m3 --device cuda
```

없으면 표 검색이 lexical 로 폴백하고, 그러면 표 후보가 달라져 기존 숫자와 비교가 안 된다.

**2. 매핑 파이프라인** (~30분, KOSIS API)

```bash
python run_kosis_measurement_pipeline.py \
  --input <BASE>/05_hcx_measurements.csv \
  --table-index kosis_table_summary.csv \
  --semantic-index data/indexes/kosis_bge_m3 \
  --out-dir <BASE>/07_mapping_v2 --device cuda
```

`prepare` → 표 검색 → 메타 수집 → validate 까지 한 번에 돈다.
`prepare` 가 `claim_item_grounded` 로 근거 없는 대상을 지우므로,
**이번에는 표 후보가 정리된 대상으로 뽑힌다** (지금까지와 다른 점).

**3. 평가 집합 잠금**

```bash
python lock_evaluation_set.py \
  --ready <NEW>/05_hcx_measurements_kosis_ready.csv \
  --output <NEW>/evaluation_set.csv \
  --excluded-output <NEW>/evaluation_set_excluded.csv \
  --manifest <NEW>/evaluation_set_manifest.json
```

**4. Chroma 좌표 인덱스** (~10분, GPU)

```bash
python kosis_build_chroma_meta_index.py \
  --meta-index <NEW>/05_hcx_measurements_kosis_meta_index.csv \
  --persist-dir data/indexes/kosis_meta_chroma \
  --collection kosis_meta_coordinates \
  --embedding-model BAAI/bge-m3 --axis-value-limit 300 \
  --prd-se-source <NEW>/05_hcx_measurements_kosis_table_candidates.csv \
  --device cuda --reset
```

manifest 의 `embedding_fingerprint` 를 기록해 둘 것. 나중에 같은 인덱스인지 확인하는 유일한 수단이다.

**5. 하이브리드 검색 + 확정** (~15분)

```bash
python kosis_chroma_hybrid_search.py \
  --claims <NEW>/evaluation_set.csv \
  --table-candidates <NEW>/05_hcx_measurements_kosis_table_candidates.csv \
  --persist-dir data/indexes/kosis_meta_chroma --collection kosis_meta_coordinates \
  --output <NEW>/chroma_candidates.csv --stats-output <NEW>/chroma_stats.csv \
  --dense-top-k 50 --lexical-top-k 50 --rerank-top-k 20 --final-top-k 10 \
  --reranker-model BAAI/bge-reranker-v2-m3 --device cuda

python kosis_validate_mapping_candidates.py \
  --input <NEW>/chroma_candidates.csv \
  --meta-index <NEW>/05_hcx_measurements_kosis_meta_index.csv \
  --output <NEW>/chroma_validated.csv \
  --evaluate-all-ranks --strict-seeded-coordinate \
  --item-top-k 1 --obj-top-k 1 --max-combinations 1 --allow-provisional
```

**`API_ERROR` 가 0 이 될 때까지 validate 를 반복 실행할 것.** 실측: 48행 → 0, 확정 11 → 12.

**6. 측정**

```bash
python report_coverage.py --validated <NEW>/chroma_validated.csv \
  --evaluation-set <NEW>/evaluation_set.csv \
  --article-source <NEW>/05_hcx_measurements_kosis_ready.csv \
  --output <NEW>/coverage.csv
# 위 결과로 재조회한 뒤 --probe 를 붙여 한 번 더 (안 하면 확정률이 부풀려진다)
```

**7. 정밀도** — 확정 건만 뽑아 `kosis_verify_claim_values.py` 로 판정.
**`불일치` 가 0 인지 반드시 확인할 것.** 이것이 커버리지보다 중요하다.

## 비교할 때

기준선은 `data/shared_20260802/` (평가 집합 88 · 확정 17 · 일치 7 · 불일치 0).

**숫자가 달라도 당황하지 말 것.** 노이즈원이 둘 있다.

| | 크기 |
|---|---|
| Chroma 인덱스 재빌드 | 골드 12건에서 ±1건 |
| KOSIS API 일시 실패 | 확정 ±1~2건 |

그리고 이번에는 **표 후보가 정리된 대상으로 다시 뽑히므로** 진짜 차이도 생긴다.
그 차이가 노이즈인지 개선인지는 `diagnose_coordinate_space.py`(분모 46)처럼
골드 없이 재는 지표로 봐야 한다. 골드 12건으로는 1건이 8.3%p 라 구분이 안 된다.

## 하지 말 것

- `05_hcx_measurements_v2.csv` · `_v3.csv` 사용 — 프롬프트 실험 실패작이다.
  품목 규칙을 넣었더니 대상 있음이 50% → 26% → 22% 로 떨어졌다(정당한 품목까지 지워짐).
- A/B 비교 중 Chroma 인덱스 재빌드
- `API_ERROR` 가 남은 상태의 커버리지 숫자 기록
- 확정 건수만 보고 개선이라 말하기 — 정밀도를 같이 볼 것.
  실측으로, 확정 12건이던 시점에 **불일치 3건이 전부 오판**이었다.
