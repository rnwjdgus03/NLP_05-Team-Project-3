# 홀드아웃 50건 — 한 번 돌리고 고치지 않는다

## 왜 필요한가

2026-08-04 기준 모든 숫자는 **같은 88건**에서 나왔다.
범위 게이트, 마진 임계값, 집계 우선 정렬, 대상 근거 검사, 지시어 전파 —
전부 그 88건을 **보면서** 만들었다.

확정 16건·불일치 0 이 실력인지 그 88건에 맞춘 결과인지 **한 번도 재지 않았다.**
골드가 12건뿐이라 자동 검사로도 못 잡는다.

## 무엇을 쓰는가

`data/holdout50_articles.csv` — 원본 풀(`검증대상_기사드랍후.csv` 2,693건)의 **51~100번**.
1~50번이 지금까지 쓴 88건의 출처다. 순서가 정확히 일치하는 것을 확인했다.

- 기간 2025-01-04 ~ 2025-01-08 (첫 50건은 2025-01-01 ~)
- `검색 구분 레이블` TRUE 46 / FALSE 4, 컬럼 구성이 첫 50건 입력과 동일
- 첫 50건과 URL 이 하나도 겹치지 않는 것을 확인했다

**작성일 형식을 반드시 확인할 것.** 아카이브 원본(`검증대상_기사드랍후.csv`)에서 잘라내면
작성일이 엑셀 일련번호(`45661`)로 나온다. 그대로 돌리면 `'작년'`이 언제인지 못 풀어
기간 추출이 통째로 깨진다. 지금 파일은 ISO(`2025-01-04`)로 되어 있다.

## 문장 분리기를 먼저 맞출 것

**첫 런은 `kss` 로 나눴다.** 이걸 안 맞추면 실험이 무의미해진다 —
문장 경계가 달라지면 추출되는 주장 자체가 달라지므로,
홀드아웃 결과가 나빠도 **일반화 실패인지 전처리 차이인지 구분할 수 없다.**

함정이 둘 있다.

| 스크립트 | `--splitter` 기본값 | 실패 방식 |
|---|---|---|
| `run_contextual_news_kosis_pipeline.py` | `kss` | 없으면 **즉시 중단** |
| `preprocess_news.py` | `auto` | 없으면 **조용히 regex 로 폴백** |

두 번째가 위험하다. 에러 없이 다른 결과를 낸다.
Colab 런타임을 새로 열면 `kss` 가 없으므로 `pip install kss` 를 먼저 해야 한다.

실측 문장 수(첫 50건, 기사 50건 기준):

| | 문장 수 |
|---|---|
| **첫 런 실제 `01_sentences.csv`** | **936** |
| `split_sentences_regex` 재현 | 1008 |
| `뉴스_데이터_정제문장.csv` | 1041 |

셋이 전부 다르다. 특히 **`뉴스_데이터_정제문장.csv` 는 파이프라인 산출물이 아니다.**
그걸 기준으로 삼으면 틀린 비교를 하게 된다.

재현 입력을 레포에 넣었다 — `data/top50_articles.csv`, `data/holdout50_articles.csv`.
전에는 첫 런 입력이 로컬에만 있어서 이 확인을 할 수 없었다.

```bash

python preprocess_news.py --input data/top50_articles.csv \

```

kss 버전이 첫 런과 다를 수 있다. **936 이 재현되면 사실상 같다고 본다.**

**2026-08-04 확인: 936 정확히 재현됐다.** 조건이 맞다.

## 규칙

1. **한 번만 돌린다.**
2. **결과를 보고 코드를 고치지 않는다.** 고치면 그 순간 홀드아웃이 아니다.
3. 고치고 싶은 것이 보이면 **적어만 둔다.** 다음 홀드아웃(101~150번)에서 검증한다.
4. 88건 결과와 나란히 놓고 **어디가 다른지만** 본다.

## 미리 적어두는 예측

결과에 맞춰 해석하지 않기 위해 **먼저** 적는다.

확정 17건 중 **14건이 무역 총계**였고 A0018·A0006 두 기사에서 나왔다.
홀드아웃 제목을 보면 은행·증권·재단·인사 기사가 14/50, KOSIS 계열 지표어는 11/50 이다.

> **확정률이 18.2% 보다 떨어질 것이다.**
> 그것은 성능 저하가 아니라 **첫 50건이 운이 좋았다는 뜻**이다.

쓸 만해 보이는 것: `배추 59%·무 77%`(소비자물가), `대중-대미 수출 격차`(무역),
`서울 집값`(주택가격동향), `현대차 미국 170만대`(모집단이 해외라 아마 거부).

**불일치는 0 이어야 한다.** 이건 도메인과 무관하게 지켜져야 하는 값이고,
여기서 깨지면 오늘 고친 것들이 88건 전용이었다는 뜻이다. 그게 이 실험의 핵심 질문이다.

## 순서

기사 ID 접두어를 **반드시 바꾼다.** 기본값 `A` 로 두면 두 런이 같은 `A0018` 을 만들고,
합칠 때 서로 다른 기사를 같은 것으로 본다.

```bash
python run_contextual_news_kosis_pipeline.py \
  --articles data/holdout50_articles.csv \
  --article-prefix H \
  --table-index kosis_table_summary.csv \
  --semantic-index data/indexes/kosis_bge_m3 \
  --out-dir <BASE>/holdout50 \
  --chunk-size 8 --overlap 2 --lead-sentences 3 \
  --device cuda --stop-after measurements
```

`--chunk-size 8 --lead-sentences 3` 은 첫 런(`contextual_top50_context_v2_8x3`)과 같은 값이다.
**다르게 주면 비교가 성립하지 않는다.**

그다음은 `docs/재실행_런북.md` 3~7번을 그대로 따른다 —
`lock` → Chroma → 검색 → validate → `report_coverage` → 정밀도.
Chroma 좌표 인덱스는 새 메타로 다시 만들어야 한다(표가 다르다).

표본이 작아 "정밀도 0%"라고 말할 수는 없다. 그러나 첫 런 16건에서 불일치가
0 이었던 것과 대비하면 우연으로 보기 어렵다.

### 불일치 4건은 전부 오판이다 — 기사는 맞다

| | 주장 | 파이프라인이 한 일 | 원인 |
|---|---|---|---|
| 1 | 소매판매액지수 **2022년 2분기** −0.2% | 2022년 **연간** 증감률 +5.88% 와 대조 | 분기를 연간으로 추출 |
| 2 | 반도체 수출 **1~11월** 1274억달러 | 2024년 **12개월** 1420억달러와 대조 | 누적 기간 무시 |
| 3 | 중국+홍콩 **비율** 51.7% | 반도체 수출액 총계에서 증감률 계산 | 구성비를 수준값에 매핑 |
| 4 | 미국+대만 비율 13.9%→21.7%, **8%p** | 위와 같은 좌표 | 구성비 변화를 수준값에 매핑 |

### 왜 가드가 안 잡았나

`extreme_error` 는 증감률에 **절대 100%p**, 수준값에 **차이율 300%** 를 쓴다.
네 건의 차이는 6.1%p · 11.5% · 9.2%p · 34.5%p 로 전부 문턱 아래다.

**가드는 설계대로 작동했다.** 그것은 좌표를 통째로 잘못 잡은 경우
(무역흑자 518억 ↔ 수입액 6320억, 1,120%)를 잡으라고 만든 것이다.
이번 네 건은 **그럴듯해 보이는 차이**라서 원리적으로 걸리지 않는다.

### 무엇을 배웠나

첫 50건의 `불일치 0` 은 **거친 오류 네 개를 고쳐서** 얻은 값이었다.
홀드아웃은 **가드가 아예 없는 실패 유형 셋**을 드러냈다.

1. **기간 단위** — 분기(Q) 주장을 연간(Y)으로 추출
2. **누적 기간** — `1~11월`, `1~9월` 같은 부분 누적
3. **구성비** — 점유율·비중 주장. `mapping_type` 에 이 개념이 없다

첫 50건은 **연간 무역 총계에 치우쳐** 있어서 이 셋이 나타나지 않았다.
확정 17건 중 14건이 무역 총계였던 것이 그 증거다.

도메인이 바뀌면 실패 유형도 바뀐다. **n=88 한 벌로 튜닝한 것은 그 한 벌에만 맞는다.**

### 가드를 넣은 뒤 (같은 날, 측정만)

`kosis_claim_shape.py` 를 만들어 세 유형을 `prepare` 에서 뺐다.

| | 첫 50건 (88) | 홀드아웃 (104) |
|---|---|---|
| 걸린 건수 | 10 | 16 |
| 그중 기존 **일치** | **0** | — |
| 확정 변화 | 16 → 15 | **4 → 0** |
| 불일치 변화 | 0 → 0 | **4 → 0** |

**거짓 불일치 4건은 전부 사라진다. 그리고 확정도 0 이 된다.**

이 도메인 묶음에서 지금 시스템이 확인할 수 있는 것은 **아무것도 없다.**
`불일치 0` 을 성과로 읽으면 안 된다 — 답을 안 하면 틀리지도 않는다.

첫 50건의 `확정 16 → 15` 는 판정보류 1건(WTO 1~9월 누적)이 빠진 것이고
**일치 7건은 그대로다.** 기존 성과는 깎지 않았다.

### 그래서 진짜 상태는

| | |
|---|---|
| 무역 연간 총계 | 작동한다 (첫 50건 일치 7) |
| 그 밖의 도메인 | **확인 가능한 것이 사실상 없다** |

첫 런의 `18.2%` 는 표본이 무역에 치우쳐 나온 값이다.
**두 숫자를 같이 보고해야 한다.** 하나만 쓰면 유리한 쪽을 고른 것이 된다.

### 다음 반복에서 볼 것 (여기서 고치지 않는다)

- `prd_se` 를 분기로 뽑는 규칙, 그리고 **분기를 확신 못 하면 확정에서 빼기**
- `1~N월` 누적 표현 탐지 → `CUMULATIVE_PERIOD_UNSUPPORTED`
- 구성비 주장 탐지 → `SHARE_CLAIM_UNSUPPORTED`
  (분자·분모 축이 둘 다 필요하다. 지금 좌표 모델로는 표현이 안 된다)

셋 다 **커버리지를 늘리는 것이 아니라 잘못된 확정을 빼는** 방향이다.
넣은 뒤에는 101~150번으로 검증한다. 홀드아웃을 보고 고쳤으므로
이 50건으로는 더 이상 검증할 수 없다.

### 두 번 재현된 것

거부 사유 1위가 `OUT_OF_KOSIS_SCOPE` 95건이다. 기사가 현대차·SKT·쿠팡 같은

시스템 한계 20건 중 최대는 `후보가 결정적이지 않음` 9건(31%)이다.

> **무역 연간 총계 밖에서는 확인율이 0 이다.**
> 한 번이면 우연일 수 있으나 **두 묶음에서 독립적으로 재현**됐다.

첫 런의 `18.2%` 는 표본이 무역에 치우쳐 나온 값이라는 것이 이제 확정적이다.
확정 17건 중 14건이 무역 총계였던 것과 일치한다.

### 이것이 뜻하는 것

지금 파이프라인은 **범용 팩트체커가 아니라 무역·물가 총계 검증기**다.
그 범위 안에서는 작동한다(일치 7, 불일치 0). 밖에서는 답을 못 한다.

길은 둘이고, **섞으면 안 된다.**

1. **범위를 좁혀 잘한다** — 대상 기사를 무역·물가·고용 등 KOSIS 강한 도메인으로
   고르고, 그 안에서 확정률과 정밀도를 올린다. 정직하고 실현 가능하다.
2. **좌표 모델을 넓힌다** — 구성비(분자·분모 두 축), 누적 기간, 분기를 표현할 수
   있게 만든다. 근본적이지만 훨씬 크다.

어느 쪽이든 **확정 0 인 상태로는 정밀도를 말할 수 없다.** 먼저 확정을 만들어야 한다.

## 좌표 모델 확장 (2026-08-04 저녁)

홀드아웃이 드러낸 세 유형 중 **둘을 열었다.** 구성비는 아직이다.

### 1단계 — 누적 기간 (`1~11월`)

`cumulative_span()` 이 `(202401, 202411)` 로 풀고, `prd_se=M` 으로 바꿔 그 구간만 합산한다.
**수준값만 연었다.** 누적 증감률은 비교 기간도 같은 폭으로 잡아야 해서 닫아뒀다.

두 번 막혔다가 뚫었다.

- `change_base` 로 판단해서 0건이 열렸다. 추출이 헐겁게 붙인다 —
  수준값 `'반도체 수출 총액'` 에도 `change_base='전년'` 이 있었다.
  `semantic_type` 으로 바꿨다.
- `share_claim` 이 문장 전체를 보고 `'수출액 1274억달러'` 까지 구성비로 잡았다.
  **구성비의 값은 항상 % 다.** `unit_dimension` 조건을 넣었다.

둘 다 **한 문장에 측정이 여럿일 때** 생기는 문제다. CES 문장과 같은 계열이다.

### 2단계 — 분기

KOSIS 분기 `PRD_DE` 형식을 실측으로 확인했다(DT_1K41012, `prdSe=Q`):
`202501 202502 202503 202504`. 분기를 **2자리로 0을 채운다.**

**월간과 글자가 같다.** `'202202'` 가 2022년 2분기인지 2월인지 구분이 안 된다.
그래서 조회·집계 전 경로에 `PRD_SE` 가드를 넣었다.

그리고 **표의 수록 주기를 어디에도 기록하지 않고 있었다.**
`getMeta type=PRD` 로 수집해 `prd_se_list` 컬럼에 담는다.

### 실측 — 이게 왜 필요했나

홀드아웃1 표 245개의 주기 분포:

| | 표 수 |
|---|---|
| `Y` 만 | 115 (47%) |
| `2년` (격년 조사) | 69 (28%) |
| `Q` 포함 | 44 (18%) |
| `M` 포함 | 30 (12%) |

**75%가 분기·월을 못 준다.**

라우팅을 켜고 다시 매칭한 결과(측정 91건, 후보 455개):

| | |
|---|---|
| 주기 불가로 빠진 후보 | **52개** (`REJECT` 사유 1위) |
| 영향받은 측정 | **18건** |
| 분기·월 주장 전체 | **21건** (M 14 · Q 7) |

`롯데백화점 설선물 매출 증가율(M) → 표는 Y 만`, `영업이익 변화율(Q) → Y 만`.
KOSIS 는 이런 요청에 에러 없이 연간값을 돌려주므로 **그대로 비교됐다.**
홀드아웃1 의 거짓 불일치는 우연이 아니라 구조적으로 예정돼 있었다.

### 정직하게 — 커버리지는 아직 안 늘었다

지금 한 일은 **잘못된 경로를 닫은 것**이다. 틀린 답 대신 판단불가가 나온다.
`Q` 를 제공하는 표가 44개, `M` 이 30개 있으므로 **라우팅으로 답할 수 있는 건이 생길 여지는 있다.**
그러나 그건 재실행으로 확인해야 하고, **홀드아웃1·2 로는 잴 수 없다**(둘 다 봤다).

### 이번 평가가 알려준 것

> **병목은 주장의 모양이 아니라 좌표 선택이다.**

**크기가 비슷한 엉뚱한 좌표**는 원리적으로 못 잡는다.

시스템 한계 46건의 내역도 같은 말을 한다 —
`후보가 결정적이지 않음` 16 (30%), `유효한 좌표 조합을 못 찾음` 10 (19%),
`좌표가 틀림` 12 (23%). **합쳐서 38건이 좌표 문제다.**

### 다음에 볼 것 (여기서 고치지 않는다 — 이 묶음도 다 봤다)

1. **선택한 좌표가 지표와 실제로 대응하는가**를 값 비교 **전에** 확인한다.
   표·항목 이름과 지표의 의미가 맞는지. 지금은 이 검사가 사실상 없다.
2. **집계 우선 정렬의 조건을 좁힌다.** `measurement_item` 이 비어 있어도
   **문장에 대상이 있으면** 집계를 고르면 안 된다.
   (`claim_specifies_target` 이 추출 필드만 본다.)
3. 3단계(구성비)보다 이게 먼저다. 구성비는 11건, 좌표 문제는 38건이다.

### 변경이 겨냥한 것

- 추출 필드가 비어도 문장에 국가·지역·품목이 있으면 집계(`계`)를 우선하지 않는다.
- 문장에 나온 값이 표의 OBJ 축에 있으면 그 좌표를 reranker 후보에 반드시 넣고 우선한다.
- 대상은 있는데 선택 좌표에서 찾지 못하면 `READY`가 아니라 `NEEDS_CONFIRMATION`이다.
- `data/seed_region_codes.csv`의 지역 어휘 108개·6체계를 사용한다.

### 실행 전 예측과 판정 기준

> **대상어가 있는 주장이 집계(`계`) 좌표로 자동 확정되는 건은 0건이어야 한다.**
> 중국·미국처럼 문장에 직접 나온 OBJ 값은 해당 축으로 이동하고,
> 축에서 찾지 못한 대상은 확정이 아니라 보류될 것이다.

> **전체 거짓 `불일치`도 0건이 목표다.** 다만 좌표 선택의 다른 실패 유형이
> 새로 나오면 실패를 숨기지 않고 기록하며, 이 묶음을 보고 즉시 고치지 않는다.

- 첫 50건 회귀 기준: 확정 16건·일치 7건이 하나도 빠지지 않아야 한다.
- 확정률은 성공 기준이 아니다. 보수적 게이트 때문에 같거나 낮아질 수 있다.
- 대상 축 선택이 실제로 발생한 건수와 `CLAIM_ITEM_MISMATCH` 보류 건수를 함께 센다.
- `API_ERROR`가 남아 있으면 결과를 기록하지 않는다.
- 실패가 나오면 수정은 다음 미사용 묶음(251~300번)에서 검증한다.

실행 식별자:

- 입력: `data/holdout5_articles.csv`
- 기사 ID 접두어: `H5`
- 출력: 홀드아웃5 전용 디렉터리
- Chroma 인덱스: 홀드아웃5 전용 경로
