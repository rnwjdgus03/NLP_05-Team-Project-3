## 2. 현재 목표와 아키텍처

최종 목표는 새로운 뉴스 기사에서도 KOSIS 표·ITEM·OBJ·기간을 정확히 선택하고,
공식 API 값과 비교해 근거 있는 판정을 내리는 것이다.

현재 구조는 다음과 같다.

```text
뉴스 주장
  -> HCX 구조화 추출(indicator / item / period / value)
  -> BGE + lexical + reranker로 관련 KOSIS 통계표 Top-N 검색
  -> SQLite로 후보 표의 ITEM / OBJ / 수록주기 exact resolution
  -> KOSIS Open API 실제값 조회
  -> MATCH / MISMATCH / 판단불가
```

벡터 검색은 비정형 표현에서 관련 표를 찾는 역할만 맡고, SQLite는 확정된 후보 표가
실제로 지원하는 구조화 좌표를 조회하는 역할만 맡는다. API 성공은 통계 의미의 정답을
보장하지 않으므로 READY 게이트와 독립 골드 평가가 별도로 필요하다.

## 3. 완료된 단계

1. v14/v15 입력·검색 기준 상태 확인
2. 잠금 주장 30건의 검색 Top-10에서 중복 제거한 통계표 294개를 대상으로 메타데이터 보강
3. 보강 SQLite로 ITEM·OBJ 좌표를 다시 선택하고 MCP 사후 근거로 개발 평가
4. 상대 월, 월·분기·연 주기, 기사 기준시점 기간 추출 오류 수정

메타데이터 보강의 최종 표별 상태는 다음과 같다.

- `DB_PRESENT`: 19개
- `HYDRATED`: 261개
- `HYDRATED_NO_PERIODICITY`: 8개
- `NO_ITM_ROWS`: 6개
- 최종 미해결 오류: 0개

과거 네트워크 오류 3행이 상태 로그에 남아 있지만 동일 표의 후속 성공 행이 존재한다.

## 4. 현재 개발 평가

평가 파일:
`outputs/locked300_v15_sqlite_coordinates_development/joint_metric_obj_v15_1/mcp_evaluation_period_v15.json`

MCP로 사후 라벨을 만든 개발 주장 7건 기준:

- 표 Recall@1: 6/7 = 85.7%
- 표 Recall@5: 6/7 = 85.7%
- 표 Recall@10: 7/7 = 100%
- 최종 표 선택 exact: 7/7 = 100%
- 최종 좌표 exact: 7/7 = 100%
- 기간 exact: 6/6 = 100%

이 수치는 7건의 개발 표본을 보면서 규칙을 수정한 결과다. 독립 일반화 성능이나 최종
서비스 성능으로 보고하면 안 된다.

## 5. 현재 중단 지점

5단계인 미사용 기사 기반 독립 검증을 시작한 직후 중단했다.
잠금 주장 30건 중 라벨 완료 7건, 미라벨 23건이다.

미라벨 article_id:

```text
A2648 A2657 A2386 A2284 A1019 A0964 A0148 A2015 A0834 A2335 A2666
A2691 A1121 A1960 A0835 A0912 A1341 A2676 A2686 A0361 A0393 A1719 A2032
```

예비 오류 분석에서 확인한 핵심 문제:

- KOSIS 공식 통계가 아닌 회사 매출·회사채 같은 사적 수치도 관련 없는 표로 과잉 매핑된다.
- 성별·지역·연령·품목 OBJ가 기사 대상과 다르면 API가 성공해도 의미상 오답이다.
- 산업·임금·인구·주택 주장 일부는 의미가 비슷한 다른 조사표를 선택한다.
- `DT_1TEC_N112` 무역집중도는 표 후보가 유력하지만 정확한 ITEM 좌표 검증이 남아 있다.
- 300인 이상 사업체 임금은 현재 선택 표가 틀렸으며 `DT_118N_MON052` 계열을 우선 검증한다.

## 6. 다음 작업 순서

골드를 더 보면서 규칙을 즉시 수정하지 말고 다음 순서를 지킨다.

1. 미라벨 23건 각각에 대해 KOSIS 제공 여부를 먼저 판정한다.
2. 제공 가능한 주장만 MCP 실제 조회로 표·ITEM·OBJ·주기·기간 골드를 만든다.
3. 제공 불가·사적 통계·파생값은 명시적으로 `NOT_KOSIS_READY`로 라벨한다.
4. 현재 동결 예측을 그대로 평가해 표 Recall@1/5/10, 좌표 exact, READY precision을 산출한다.
5. 오류를 표 검색, HCX 구조화, ITEM, OBJ, 기간, 비대상 게이트로 분해한다.
6. 개선 규칙은 개발 표본에만 적용하고 별도의 새 미사용 홀드아웃으로 재검증한다.

현재 23건을 모두 라벨하기 전에는 v15 일반화 성능을 확정하거나 100%라고 표현하지 않는다.
